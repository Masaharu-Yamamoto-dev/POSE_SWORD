# 2026-08-20 11:00:00 — POSE_SWORD 全体総まとめ

## 1. このリポジトリの全体像

このリポジトリは、単一の Web アプリではなく、3層で構成されるシステムです。

1. フロントエンド: React + Vite
2. AI/画像処理サーバー: FastAPI + Python
3. ゲーム本体: Unity WebGL

これらの役割を分離して、画像を撮影して AI に処理させ、その結果をゲームのステータスとして使う流れを実現しています。

---

## 2. 画像処理の役割

[image-process/server.py](image-process/server.py) は、React 側から `imageData` を受け取り、base64 画像を変換、人物を切り抜き、ステータス計算をして、最終的に JSON を返す API です。

この処理の中核は次の3つです。

- [image-process/person_cutout.py](image-process/person_cutout.py)
  - 背景除去と人物切り抜き
- [image-process/stats.py](image-process/stats.py)
  - 姿勢やシルエットから stat を計算
- [image-process/server.py](image-process/server.py)
  - API 層として呼び出しと返却を担当

### 処理フロー

1. React から base64 画像を送信
2. `decode_image()` で PIL の画像に変換
3. `cutout_person()` で背景除去
4. silhouette と pose を抽出
5. `compute_stats()` で attack / weight / hp を計算
6. PNG を base64 で返却
7. 剣名やボックス情報も JSON として返却

## 3. server.py の全体構造

[image-process/server.py](image-process/server.py) の大きな構造は次のとおりです。

### ルート

- `GET /health`
  - 健康状態確認
- `POST /cutout`
  - 画像処理の本体

### 主要な要素

- `CutoutRequest(BaseModel)`
  - リクエスト body の型定義
- `FastAPI()`
  - アプリ本体
- `CORSMiddleware`
  - ブラウザアクセス用 CORS 設定
- `_API_KEY`
  - 認証トークンがあれば要求する

### `cutout` の流れ

```python
@app.post("/cutout")
def cutout(req: CutoutRequest, x_api_key: str = Header(None)):
    if _API_KEY and x_api_key != _API_KEY:
        raise HTTPException(status_code=401, detail="Unauthorized")

    try:
        original = decode_image(req.imageData)
    except ValueError as e:
        raise HTTPException(status_code=400, detail=str(e))
```

これは、

- 認証失敗時は 401
- 画像が不正なときは 400

という HTTP レスポンスに変換している処理です。

## 4. BaseModel とは何か

`BaseModel` は Pydantic のクラスで、JSON の入力形式と型を定義するものです。

このプロジェクトでは次のように使われています。

```python
class CutoutRequest(BaseModel):
    imageData: str
    userName: str = ""
```

これにより、FastAPI は JSON リクエストを自動的に `req.imageData`、`req.userName` のような Python オブジェクトに変換します。

### なぜ使うのか

- 型を明示できる
- 不正な JSON を弾ける
- `req` から安全に値を取り出せる
- API ドキュメントにも自動反映される

## 5. Python の例外と HTTPException

### ValueError

`ValueError` は「値が不正」という Python の標準例外です。

この API では base64 変換や画像デコードが失敗したときに発生し得ます。

```python
except ValueError as e:
    raise HTTPException(status_code=400, detail=str(e))
```

ここで `as e` は例外オブジェクトそのものを受け取る記法です。`str(e)` でメッセージを文字列化して、クライアントに返せます。

### HTTPException

これは FastAPI 用の例外です。Python の例外を HTTP レスポンスに変換する役割があります。

```python
raise HTTPException(status_code=401, detail="Unauthorized")
```

これにより、クライアントは 401 を受け取ります。

### `raise` と `return`

- `return`: 正常終了して値を返す
- `raise`: 異常終了して例外を投げる

```python
def ok():
    return {"status": "ok"}

def bad():
    raise ValueError("失敗")
```

前者は正常系、後者はエラー系です。

## 6. APIキーが設定されている場合の意味

[image-process/server.py](image-process/server.py) は次のように定義されています。

```python
_API_KEY = os.environ.get("API_KEY", "")
```

これは、環境変数 `API_KEY` が設定されているかどうかを見ている処理です。

### どういう場合か

- ローカル開発時: API_KEY が空なら認証なし
- Hugging Face Spaces: Secrets に `API_KEY` を入れて利用
- 本番運用: クライアントから `X-API-Key` ヘッダーでキーを送る

もし `API_KEY` が設定済みなら、

```python
if _API_KEY and x_api_key != _API_KEY:
    raise HTTPException(status_code=401, detail="Unauthorized")
```

によって、認証が一致しないと 401 を返します。
